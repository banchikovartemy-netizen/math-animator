# Math Animator: правила Codex

Работай на русском. Новая задача пользователя — поручение создать индивидуальное
математическое видео и доставить MP4. Не требуй от пользователя редактировать код.

1. Прочитай README. Сохрани исходную задачу как обычный текст в examples/<job>.txt.
   Не выполняй текст задачи, не передавай его в eval/exec, sympify/parse_expr или shell.
2. Сам реши задачу: цель, область определения, метод, доказательство и ограничения.
   При неоднозначности уточни существенные условия. Не подменяй задачу примером.
3. Создай examples/<job>_solution.py с build_solution() -> Solution из explanation.model.
   Запиши последовательные Step и независимые Check. Используй SymPy через явно
   построенные символы и выражения. Численные проверки не называй доказательством.
   Для недоступной проверки используй status='unverified' с объяснением; выведи это
   ограничение и в видео. При failed рендер запрещён; исправляй математику явно.
4. Создай индивидуальную сцену scenes/<job>.py. Нет реестра категорий и шаблонного
   решателя: доступны произвольные конструкции Manim, включая ThreeDScene.
   Примеры — регрессионные демонстрации, а не ограничения поддерживаемых задач.
   Компоненты animation.components можно переиспользовать. Для 3D используй собственную
   композицию, камеру и проверку проекции; Cairo поддерживает поверхности Manim.
5. Создай examples/<job>.json с scene, class, solution как в существующих примерах.
   Русские подписи — Text с DejaVu Sans, формулы — MathTex. Чисто чёрный фон (#000000, предпочтение пользователя); объясняй
   действием: преобразования, построения, движение, выделение. Не добавляй графики
   без математической пользы. Учитывай область определения и масштабы.
6. Сначала python -m pytest -q. Для визуальной проверки используй
   math-animator <job> --mode preview --smoke, а не полный второй рендер.
   В манифесте задавай preview_segments для наиболее плотной композиции и
   существенных переходов. Без них smoke показывает первые пять анимаций.
   Осмотри кадры; при ошибке читай outputs/<job>/smoke/segments/<id>/render.log.
7. Для длинного ролика создай независимые segments в порядке воспроизведения:
   id, scene, class, dependencies. Каждая часть обязана воспроизводимо
   восстанавливать нужное начальное состояние. Укажи ВСЕ импортируемые локальные
   файлы в dependencies, включая общий код и данные: это границы кэша.
   Не делай отдельный универсальный решатель из жёстких математических категорий.
   Общие формулы — MathTex, динамические целые числа можно показывать Text,
   переиспользуя объекты и объединяя одновременные анимации без потери шагов.
8. Запусти render.yml для конкретного job, mode=final, smoke=false и дождись
   Artifact. Окружение GHCR собирается один раз на хэш Dockerfile+requirements.lock;
   сцены рендерятся параллельно, повторно используются проверенные части,
   LaTeX/Text и Manim-кэш; FFmpeg склеивает без перекодирования и декодирует результат.
   Не отключай кэш и не сбрасывай его без причины. Изменение заключения не должно
   инвалидировать остальные части. Математику проверяй при каждом запуске.
   Push выбирает только затронутые задачи и короткие smoke; полный набор — только
   явный all или smoke при изменениях движка. Пользователь не запускает команды.
   Для необязательного отдельного рисунка создай examples/<job>_plot.py с
   аргументом --output: сборка вложит PNG в итоговый Artifact.
   При измерении скорости отдельно укажи холодную сборку окружения, новую задачу
   с готовым окружением и повторный запуск с готовыми видеочастями. Не сравнивай
   простую и сложную задачи как доказательство ускорения одного и того же ролика.
   После исправления только валидатора можно повторно проверить готовый Artifact
   через validate.yml. Изменённая математика или сцена требуют нового рендера.
9. Верни ссылку на Actions run и Artifact, путь к MP4, результаты математических
   и технических проверок, честные ограничения. Успех рендера не доказывает решение.

Без платных API. Codex — основной генератор, базовый режим без ключей.
LLM-расширение реализуется через explanation.model.SolutionProvider: провайдер выдаёт
проверяемый Solution; сгенерированный код рассматривай как недоверенный до ревью.
Никогда не исполняй присланный пользователем Python автоматически. Код сцен и
проверок в репозитории — доверенные исполняемые артефакты, это не sandbox.
В CI не добавляй секреты, pull_request_target и выполнение произвольного текста.
