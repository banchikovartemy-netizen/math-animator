# Math Animator

Индивидуальные математические анимации на Python и Manim Community. Основной
генератор объяснения и кода — Codex; SymPy проверяет явно сформулированные
утверждения. Проект не изображает автономный решатель произвольного русского текста.

Готовый пример: [скачать Final MP4 в артефакте](https://github.com/banchikovartemy-netizen/math-animator/actions/runs/43459120053/artifacts/14055716523)
(1080p/30 FPS, интегрирование по частям).
[Успешный облачный рендер пяти примеров](https://github.com/banchikovartemy-netizen/math-animator/actions/runs/43459076354).

Новый подробный пример: [две матрицы 5×5 — скачать видео](https://github.com/banchikovartemy-netizen/math-animator/actions/runs/43463543503/artifacts/14058015143)
(1080p/30 FPS, около 6:37, чисто чёрный фон, все 125 умножений и 100 сложений).
[Письменный разбор](examples/matrix5_solution.md) · [Проверки](MATRIX5_VALIDATION.md).
Чисто чёрный фон `#000000` установлен по умолчанию для ExplainedScene.

## С телефона через Codex Cloud

Выберите этот репозиторий и отправьте задачу, например:

> Создай видео: вычислить ∫ x eˣ dx методом интегрирования по частям.
> Проверь ответ и пришли финальный MP4 через GitHub Actions.

Codex читает AGENTS.md, сохраняет условие, пишет индивидуальные решение, проверки
и сцену, рендерит preview, проверяет кадры, исправляет ошибки, затем создаёт final.
API-ключ не нужен. Новая задача не обязана принадлежать одному из примеров:
можно писать произвольный Manim, включая 3D, геометрию, алгоритмы и поверхности.
При недостаточных условиях Codex уточняет их; недоказанные утверждения маркирует.

## Получение MP4

Откройте вкладку **Actions → Render mathematics → нужный запуск → Artifacts**.
Артефакт `math-<job>-<mode>` содержит MP4, solution.json, report.json и логи.
На телефоне скачайте ZIP и откройте MP4. Требуется вход в GitHub; срок хранения
артефактов 30 дней. Публикация сайта и регистрация в сторонних сервисах не нужны.

Push изменений выбирает затронутые задачи и делает короткий smoke-preview.
Изменение общего движка запускает smoke-набор; полный набор задаётся явным `all`. Кнопка **Run workflow** позволяет выбрать `job` (`all` или имя
манифеста) и `final`. Workflow должен находиться в основной ветке, чтобы кнопка
ручного запуска появилась. Codex может подготовить рабочую ветку/PR и проверить
автоматический запуск без слияния. GitHub Actions использует доступную квоту
аккаунта; платные внешние сервисы проект не вызывает.

## Окружение

Python ≥3.11. Прямые зависимости закреплены в pyproject.toml, полное разрешение
Python-пакетов — requirements.lock. Системные пакеты APT получают обновления
Bookworm: побайтовая воспроизводимость ОС не гарантируется. Docker основан на Python 3.11.11 (digest закреплён) с Manim 0.19.0, LaTeX,
FFmpeg и шрифтами. Обновляйте lock и базовый образ осознанно.

```bash
docker build -t math-animator .
mkdir -p outputs && chmod 777 outputs
docker run --rm --network none -v "$PWD/outputs:/app/outputs" math-animator integration --mode preview
```

Локальная установка (Debian/Ubuntu, системные зависимости устанавливает владелец
окружения): build-essential, pkg-config, libcairo2-dev, libpango1.0-dev, ffmpeg,
texlive-latex-extra, texlive-fonts-recommended, texlive-science, dvisvgm,
fonts-dejavu-core. Затем:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
pip install --no-deps -e .
python -m pytest -q
math-animator integration --mode preview
math-animator integration --mode final
```

Видео: `outputs/<job>/<mode>/<job>.mp4`. Preview: 1280×720/24 FPS;
Final: 1920×1080/30 FPS; H.264/MP4, 16:9, русский текст. Аудио пока нет.
Продолжительность определяет индивидуальная сцена. Вертикальный формат пока
не реализован: профили централизованы в validation.video.PROFILES, но 9:16
требует отдельной перекомпоновки сцен, а не простого изменения разрешения.

## Архитектура

| Компонент | Назначение |
| --- | --- |
| `src/math_engine` | Символьные проверки, passed/failed/unverified; блокировка ошибочного результата |
| `src/explanation` | Solution, Step и протокол подключаемого SolutionProvider |
| `src/animation` | Композиция, формулы, переходы, проверка границ |
| `scenes` | Индивидуальный доверенный код Manim |
| `src/rendering` | CLI, манифесты, изолированные каталоги, логи и отчёты |
| `src/validation` | ffprobe, H.264/FPS/размеры, полное декодирование FFmpeg |

`SolutionProvider` — точка расширения для будущего LLM API; готового API-адаптера
и автоматического исполнения ответа LLM нет. Можно добавить адаптер без изменения
рендера, но требуется ревью решения и сгенерированного кода.

## Проверки и примеры

`integration`, `derivative`, `geometry`, `matrix`, `graph` — пять регрессионных
демонстраций разных визуальных методов. Это примеры, не обработчики разделов.
Проверки SymPy и независимый BFS выполняются перед рендером. `failed` останавливает
рендер; `unverified` сохраняется в отчёте и требует явной оговорки в объяснении.
Произвольный пользовательский текст никогда не интерпретируется как Python.
Сцены и проверки — исполняемый код репозитория, они требуют доверия и ревью.
CI рендерит без сети и без секретов; это не защитная песочница для враждебного кода.

`ExplainedScene` проверяет границы объектов на каждом кадре и сохраняет layout.json.
`check_frame` также доступен для дополнительных явных проверок.
Автоматического доказательства отсутствия пересечений, качества композиции и
математической верности графика нет: Codex должен осматривать кадры и сверять
формулы. Успешный FFmpeg и успешный Manim подтверждают техническую корректность,
а не математическое доказательство. См. VALIDATION.md для фактического отчёта.

## Повторная проверка длительного рендера

`Revalidate rendered artifact` (`validate.yml`) принимает ID предыдущего запуска,
имя задачи и режим. Он скачивает уже созданный MP4, повторно проверяет математику,
размеры, FPS и полное декодирование, затем сохраняет артефакт `-verified`.
Решение должно полностью совпадать с исходным отчётом; изменение задачи или
анимации требует нового рендера. Первоначальная ошибка сохраняется в отчёте.
Номинальный FPS проверяется точно; для среднего FPS допускается погрешность
метаданных до 0,0001 кадра/с при склейке сотен клипов Manim.

## Быстрый рабочий цикл

1. Готовый образ `ghcr.io/<owner>/<repo>/renderer:env-<hash>` включает Manim,
   LaTeX, FFmpeg и закреплённые зависимости. Он создаётся один раз workflow
   `runtime.yml`, затем используется без установки пакетов. Ключ меняется только
   при изменении Dockerfile или requirements.lock. Доступ через штатный GITHUB_TOKEN,
   ручные ключи и регистрация не нужны.
2. Codex задаёт один job. На push планировщик выбирает только затронутые задачи
   по зависимостям манифеста; документация не запускает рендер.
3. `--smoke` использует preview_segments. Для старых сцен без такой настройки
   проверяются первые пять анимаций. Это выборочная проверка композиции, не полный ролик.
4. `segments` рендерятся независимыми GitHub jobs (до 8 одновременно), затем
   склеиваются в порядке манифеста через FFmpeg `-c copy`. Для матриц 5×5 это
   вступление, пять строк и заключение. Для integral_graph — шесть отдельных сцен.
5. В матричном ролике объединены одновременные анимации, а повторяющаяся числовая
   арифметика показывается шрифтовыми объектами вместо новой компиляции LaTeX для
   каждой пары. Число показанных математических действий сохранено.
6. Actions Cache сохраняет готовые MP4-части с SHA-256, LaTeX/Text и Manim partials.
   Ключ части учитывает её код, явно объявленные зависимости, код рендера,
   математические данные, окружение и профиль. Математические проверки выполняются
   заново. Ошибочная, устаревшая или повреждённая часть не попадёт в итоговый ролик.

Кэш имеет квоты и может быть вытеснен GitHub; тогда часть рендерится заново.
Параллельность сокращает ожидание, но может увеличить расход runner-minutes.
Время очереди GitHub и скачивания окружения сохраняется даже при готовом видеокэше.

```bash
math-animator integral_graph --mode preview --smoke
math-animator integral_graph --mode final --workers 3
math-animator integral_graph --mode final --segment points
```

Отдельные части и их timings/cache_hit записываются в
`outputs/<job>/<mode>/segments/<id>/segment.json`, общий отчёт — в report.json.
Финальный Artifact содержит MP4, математический отчёт и необязательный graph.png.
Для короткой проверки используется каталог `outputs/<job>/smoke`.

Чтобы корректно переиспользовать кэш, перечисляйте все локальные импорты части
в dependencies. Необъявленные зависимости не обнаруживаются автоматически.
Смена только модуля заключения сохраняет кэш остальных сцен. Профили preview и
final разделены; их видео никогда не подменяют друг друга.
